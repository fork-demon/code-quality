# Code Quality Pack

Pluggable code-quality guard rails for AI coding agents. When a lot of code is
generated by agents, prompts alone don't guarantee quality — this pack layers
**always-on skills** (steering), **commands** (on-demand review), and a
**static-analysis hook gate** (enforcement) that any skills/hooks-capable agent
(Tabnine, Claude Code, Gemini CLI/Antigravity, Cursor, ...) can use.

```
skills/     SKILL.md files (open Agent Skills standard) — active by default
commands/   TOML slash commands, incl. multi-agent review
tools/      qcheck.sh — simple Checkstyle+PMD gate driven by config
hooks/      run the gate after each agent iteration; block until clean
```

## The layers

| Layer | What | Guarantees |
|---|---|---|
| Skills | Generic quality standards the agent applies while writing: design principles, design patterns, test best practices, how to fix analysis findings | Better code by default (advisory) |
| Commands | `/quality-review` (4 parallel reviewer lenses: design, tests, maintainability, security), `/design-review` (before implementation), `/quality-gate` (run + fix) | Structured review on demand |
| Hook gate | `tools/qcheck.sh` runs curated Checkstyle + PMD rulesets on changed files after each agent iteration; hook blocks the agent from declaring "done" until findings are fixed | Deterministic floor — code that fails the gate cannot ship |

## Skills

- **code-quality-core** — applies to every change: SOLID, small units, error
  handling, immutability, security basics, definition of done.
- **design-patterns** — symptom → pattern decision table; anti-patterns;
  over-engineering is a finding.
- **writing-good-tests** — behavior over implementation, edge cases, AAA,
  deterministic tests, test-double discipline.
- **fixing-static-analysis-findings** — the fix loop for gate failures; never
  edit the gate to pass the gate.
- **multi-agent-quality-review** — the four-lens parallel review protocol used
  by `/quality-review`.

## The gate: qcheck

```bash
tools/qcheck.sh                 # checks Java files changed in the working tree
tools/qcheck.sh src/Foo.java    # or explicit files
```

- Downloads pinned Checkstyle/PMD once to `~/.qcheck/tools` (needs `java`,
  `curl`, `unzip`).
- Config in `tools/config/qcheck.conf` (enable/disable tools, versions,
  ruleset overrides, findings budget).
- **Optional Snyk + Sonar** (off by default): `SNYK_ENABLED` runs
  `snyk code test` (SAST), `SNYK_DEPS_ENABLED` runs `snyk test` (vulnerable
  dependencies), `SONAR_ENABLED` runs `sonar-scanner` and fails the gate when
  the server-side quality gate fails (`sonar.qualitygate.wait`). These scan
  the whole project and need their own auth (snyk CLI + `snyk auth`;
  sonar-scanner + `SONAR_HOST_URL`/`SONAR_TOKEN`), so enable them for
  pre-commit/CI or `/quality-gate` runs — keep the per-iteration hook on the
  fast Checkstyle/PMD pair.
- Curated rulesets in `tools/config/` — correctness/security/design signal
  only, no formatting noise.
- Exit codes: `0` pass, `1` findings over budget, `2` execution error.

## Installing per agent

**Tabnine (CLI agent)** — skills: place `skills/` dirs where Tabnine discovers
Agent Skills; hook: merge `hooks/tabnine-settings.json` into
`<project>/.tabnine/agent/settings.json` (fix the path). The `AfterAgent` hook
denies task completion with the findings list until the gate passes.

**Claude Code** — skills: copy/symlink `skills/*` into `.claude/skills/`;
hook: merge `hooks/claude-code-settings.json` into `.claude/settings.json`
(`Stop` hook blocks finishing while the gate fails). Commands: the TOML
commands translate 1:1 into `.claude/commands/*.md` if desired.

**Gemini CLI / Antigravity** — commands: copy `commands/*.toml` into
`.gemini/commands/` (or the agent's command dir); skills per its skills
support.

**Any other agent / CI backstop** — run `tools/qcheck.sh` in a git pre-commit
hook or CI step; it's agent-independent:

```bash
# .git/hooks/pre-commit
bash /path/to/code-quality/tools/qcheck.sh || exit 1
```

## Design notes

- Generic by intent: the skills cover universal quality (not framework
  specifics); rulesets target Java. Other languages = swap the tool layer,
  keep skills/commands.
- Prompts steer, the gate enforces: the agent is told to fix root causes, and
  the hook re-runs the same deterministic check — the agent cannot talk its
  way past it.
- Maintenance surface: markdown, two ruleset XMLs, one ~140-line shell script.
